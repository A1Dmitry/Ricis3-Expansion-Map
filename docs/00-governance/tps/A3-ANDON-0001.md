# A3 — ANDON A-0001/A-0002: нормативный документ описывал несуществующее

**Дата:** 2026-09-15 · **Владелец:** агент (автономный цикл RCVAP) · **Процесс:** [`../TOYOTA_TPS_WORKING_SYSTEM.md`](../TOYOTA_TPS_WORKING_SYSTEM.md)
**Карточка:** `TPS-0001` · **Андон:** `A-0001` (high), `A-0002` (medium) · **Кайдзен:** `K-0001`, `K-0002`

Формат A3 (Тойота): фон → текущее состояние → цель → анализ первопричины → контрмеры → план → проверка. Ниже каждый раздел опирается только на воспроизводимые факты; там, где факта нет, это написано явно.

## 1. Фон

Проект управляется тремя нормативными документами (AGENTS.md, RCVAP, WORK_PATTERNS) и реестрами доказательств. RCVAP запрещает выдавать декларацию за результат в **математике**; в **документации и процессах** такой запрет держался только на ревью по тексту. Первый такт работы по Toyota-шаблону потребовал ответить на вопрос Тойоты: *что именно останавливает линию, если брак обнаружен?* — и обнаружил, что останавливать нечего: для документации машины-гейта не существовало.

## 2. Текущее состояние (genchi genbutsu — фактические замеры, не пересказ)

| Проверка | Факт |
|---|---|
| `ls docs/` | `00-governance`, `01-architecture`, `05-evidence`, `russian-resource-manifest.json` — **4 каталога из описанных в каталоге отсутствуют**: `02-sprints`, `03-quality`, `04-history`, `06-canonical-template` |
| `DOCUMENTATION_CATALOG.md` | перечисляет все 8 каталогов в одном формате таблицы, без единого маркера «этого ещё нет»; раздел «Проверка завершения» требует, чтобы «каждый прежний Markdown file доступен ровно по одному versioned path» |

Класс дефекта **не выдуман ради доски**: он того же рода, что закрытые находки F-02/F-04/F-14 в `artifacts/proofs/core-checks/kernel-findings.json` — статус/заявление без фактического прогона.

## 3. Цель

1. Ни один нормативный документ не может утверждать существование пути, которого нет, — без явной метки «целевая структура».
2. Ни одна относительная ссылка в репозитории не ведёт в никуда.
3. Оба условия проверяются машиной на каждом PR, а не обещанием в тексте.
4. Никаких побочных изменений: статусы доказательств, формулировки узлов и содержимое реестров не трогаются.

## 4. Анализ первопричины (5 почему)

1. **Почему читатель считал каталоги существующими?** Строки таблицы не различают «есть» и «будет» — различается только колонка нормативности.
2. **Почему документ описывал незавершённое как завершённое?** Каталог написан как *итог плана* миграции; план был выполнен частично (перенесли 00/01/05), и текст не синхронизировали с фактом.
3. **Почему расхождение пережило ревью?** Ни один страж не сопоставлял пути из документов с деревом; ревью читало текст, а текст неопровержим сам в себе.
4. **Почему стража не было?** Требование проверки ссылок оставили ответственностью человека, потому что «документ не может сломать сборку».
5. **Почему это считалось допустимым?** В проекте машина контролировала только код и Lean-артефакты; governance-слой считался вне зоны действия пока-ёке.

**Корень:** нормативный документ, описывающий структуру, не имеет внешнего источника истины → он может лгать без какого-либо сигнала. Это подмена основания (декларация вместо факта) — тот же класс ТУФТЫ, что и «статус без прогона ядра», только в слое процессов.

## 6. План исполнения (one-piece flow)

`ready → in_progress` (реализация гейта) → `verify` (атака на результат + прогоны) → `done` только при `tps:gate` = 0. Карточки, которые этот ремонт касается, заведены в доске отдельно (`TPS-0002`…`TPS-0008`), смешивать их с этим A3 нельзя.

## 7. Проверка и обратная связь (факт, а не намерение)

- До ремонта: гейт падает на `CATALOG_PATH_MISSING` ×4 и `DOC_LINK_BROKEN` ×1 (после того, как сам стандарт завёл ссылку на ещё не сгенерированный `tps/BOARD.md`, гейт **сразу это поймал** — первый реальный сработавший сигнал, а не демонстрация).
- После ремонта: `npm run tps:gate` → exit 0; `npx vitest run tools/tpsStandardWork.test.ts` → 30/30; `npm test` и `npm run lint` — результат в карточке `TPS-0001`.
- **Находка при написании мутационных тестов:** проверка маркера аудитора стояла *после* раннего выхода при пустом списке команд — то есть карточка с `commands: []` проходила бы мимо `DONE_SELF_CERTIFICATION`. Тест «refuses self-certification wording … even with no commands at all» это зафиксировал, порядок проверок изменён, тест зелёный. Класс именно тот, против которого направлен K-0002: страж, который нельзя покраснеть, не является доказательством.

## 8. Ёкотэн (горизонтальное распространение)

Проверено тем же классом: `docs/00-governance/DOCUMENTATION_CATALOG.md`, `docs/00-governance/DEFERRED_LOCALIZATION_TASK.md` (оттуда и взята найденная битая ссылка), `artifacts/proofs/README.md`, `ACTIVE_TASKS.md`, новый стандарт и вся доска. Полное покрытие — гейтом по всем markdown-файлам репозитория.

## 9. Остаточный риск

Гейт знает только про пути и форму. Он не отличает «каталог существует» от «каталог полезен», и не проверяет содержательность ни одного статуса — это зафиксировано открытым андоном `A-0003` и остаётся до решения владельца по F-05/F-09…F-11.
