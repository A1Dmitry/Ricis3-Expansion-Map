## Андон-журнал (полный)

### `A-0001` · high · CLOSED — Нормативный каталог описывает четыре каталога, которых нет в дереве

- **Факт:** `ls docs/` даёт ровно 00-governance, 01-architecture, 05-evidence (+ russian-resource-manifest.json), тогда как DOCUMENTATION_CATALOG.md строки таблицы перечисляют `docs/02-sprints/`, `docs/03-quality/`, `docs/04-history/`, `docs/06-canonical-template/` без единого маркера «этого ещё нет». Проверка выдала: 4 MISSING, 2 EXISTS.
- **Почему 1:** Почему читатель (и агент) считается каталоги существующими? — Строки таблицы поданы как описание текущего дерева, а не целевой структуры, и отличаются только колонкой «Нормативность».
- **Почему 2:** Почему документ описывал незавершённую миграцию как завершённую? — Каталог писался как итог плана миграции и пережил частичное выполнение плана: перенесли 00/01/05, остальные каталоги не создали.
- **Почему 3:** Почему расхождение не всплыло раньше? — Ни один страж не сверял пути из нормативных документов с фактическим деревом; CONTRIBUTING требует «проверку broken links до commit», но требование никто не исполнял машиной.
- **Почему 4:** Почему проверка осталась устной? — Класс проверки «заявлено/фактически» считался обязанностью ревью (AGENTS.md §9), а ревью в этом проекте выполнялось по тексту, а не по дереву.
- **Почему 5:** Почему ревью по тексту не ловит такие дефекты? — Текст неопровержим сам в себе: противоречие видно только при сопоставлении с файловой системой, то есть нужен внешний источник истины (fs), а не читатель.
- **Корень:** Нормативный документ, описывающий структуру репозитория, не имеет машины-источника истины: он может утверждать несуществующее без какого-либо падения проверки. Это подмена основания (декларация вместо факта) на уровне governance-слоя — ровно тот класс ТУФТЫ, который RCVAP запрещает в доказательствах, но не запрещал в документации.
- **Контрмера:** Две меры вместо латания текста: (1) DOCUMENTATION_CATALOG.md переписан честно — отсутствующие каталоги помечены маркером `ЦЕЛЕВАЯ СТРУКТУРА (в дереве отсутствует)`, существующие описаны как фактические; (2) пока-ёке `validateDocumentationConsistency` сверяет каждую строку каталога с деревом и рвёт CI, если путь отсутствует, а маркера честности нет.

### `A-0010` · high · CLOSED — Приложение не отображается: dev-сервер Vite отклонял проксированный хост превью (403 до SPA-мидлвари)

- **Факт:** `curl -s -i -H 'Host: <preview-host>' http://localhost:3000/` → `HTTP/1.1 403 Forbidden`, тело: `Blocked request. This host ("3000-i1nfmt1owr5psuyk5cyv4.e2b.app") is not allowed. To allow this host, add … to \`server.allowedHosts\``; при этом `curl` на `localhost:3000` → `200`. Платформа превью сообщает о блокирующем ответе при старте процесса: `Port 3000 REJECTS the user's preview host … (HTTP 403 …)`. В `server.ts` стояло `allowedHosts: process.env.VITE_ALLOWED_HOSTS === "true" ? true : undefined`, а переменную не выставляет ни платформа, ни скрипты, ни `.env*`. Настройка внесена апгрейдом `e5bd034` (2026-08-17, `vite ^5.3.4` → `^8.2.1`); проверка хоста существует в Vite 6.0.9+/5.4.12+/4.5.6+ (DNS-rebinding), в 5.3.4 её нет.
- **Почему 1:** Почему превью пустое? — Проверка хоста Vite отдаёт 403 раньше SPA-мидлвари: браузер не получает ни документа, ни модулей, поэтому кода приложения в браузере нет и клиентской ошибки для диагностики не существует.
- **Почему 2:** Почему проверка хоста срабатывает? — `server.allowedHosts` по умолчанию `[]`, а встроенно разрешены только `localhost`, `*.localhost`, IP-литералы и `file:`/`-extension:`; приложение в песочнице и под Cloud Run доступно исключительно через прокси, чей хост в этот список не попадает.
- **Почему 3:** Почему настройка не спасала? — Она была opt-in (`VITE_ALLOWED_HOSTS === "true"`), а включающего внешнего действия не делает никто: мера, требующая действия, которое не выполняется, не отличается от отсутствия меры.
- **Почему 4:** Почему этого не видели гейты? — Ни один прогон репозитория не проходит через транспорт dev-сервера: `vitest` работает в jsdom и не монтирует Vite-мидлварь, `vite build` не читает `server.*`, Pages получает статику, `npm start` отдаёт `dist/` без Vite. Линия `lint`/`test`/`build` зелёная при полностью неработающем канале превью.
- **Почему 5:** Почему дефект появился незаметно? — Апгрейд тулчейна (`vite ^5.3.4` → `^8.2.1`, 2026-08-17) сменил дефолт безопасности зависимости, а транспортный контракт dev-канала не был ни задан явно, ни покрыт проверкой — менять поведение было нечему противоречить.
- **Корень:** Транспортный контракт dev-канала (в каком окружении и под каким `Host` реально работает приложение) не был задан явно и не покрыт ни одной проверкой. Поэтому смена дефолта в зависимости (Vite: разрешены только localhost/IP) прошла молча, а «зелёная» линия проверок этот канал не пересекала: 2000+ тестов и успешный деплой сосуществовали с полностью недоступным превью.
- **Контрмера:** Единая политика хостов `resolveDevAllowedHosts()` в `server/devHostPolicy.ts`, применённая ко всем точкам входа Vite (`server.ts` → `server.allowedHosts`, `vite.config.ts` → `server.allowedHosts` и `preview.allowedHosts`); политика opt-out (проксированные хосты разрешены без внешних переменных), сужение — явными значениями `false`/списка; стартовый лог политики; регрессионный страж с настоящей HTTP-пробой через Vite-мидлварь и контрольной пробой строгого режима (403), чтобы тест не был вакуумным; документирование переменной и симптома в `.env.example` и `README.md`.
- **Перепроверка:** `npm run tps:gate` → exit 0
- **Ёкотэн:** `vite.config.ts` — Сверено: вторая точка входа Vite (`npx vite` без `server.ts`) получала тот же дефолт `[]` — политика подключена к `server.allowedHosts`.
- **Ёкотэн:** `.env.example` — Сверено: переменная и симптом не были задокументированы нигде; добавлено описание политики и последствий каждого значения.
- **Ёкотэн:** `README.md` — Сверено: у пользователя не было способа связать пустое превью с проверкой хоста; добавлен симптом → причина → способ сужения.
- **Ёкотэн:** `server/devHostPolicy.test.ts` — Сверено: проба включает контрольную сторону (строгий режим обязан дать 403) — иначе страж не может покраснеть и не является защитой.
- **Ёкотэн:** `docs/05-evidence/architecture/incident-2026-09-16-preview-not-displaying.md` — Сверено: зафиксированы временная линия по коммитам, отброшенные гипотезы с основаниями и ручное воспроизведение «до/после».
- **Изменение стандарта:** `server/devHostPolicy.ts` + `server/devHostPolicy.test.ts` (10 тестов: HTTP-проба по умолчанию/строгий режим/allowlist + контракт точек входа), правки `server.ts` и `vite.config.ts`, документирование в `.env.example`/`README.md`, разбор в `docs/05-evidence/architecture/incident-2026-09-16-preview-not-displaying.md`.
