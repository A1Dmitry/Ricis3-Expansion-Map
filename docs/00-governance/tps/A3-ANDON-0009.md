# A3 — ANDON A-0009: слепой страж перепроизводства (зелёный при невидимых данных)

**Дата:** 2026-09-16 · **Владелец:** агент (автономный цикл RCVAP) · **Процесс:** [`../TOYOTA_TPS_WORKING_SYSTEM.md`](../TOYOTA_TPS_WORKING_SYSTEM.md)
**Андон:** `A-0009` (high) · **Карточка:** `TPS-0010` · **Кайдзен:** `K-0012` · **Потеря:** `M-0009`

## 1. Фон

Правило `CARD_FINDING_ALREADY_CLOSED` введено в такте 2 (`TPS-0009`, контрмера к `A-0008`): карточка в потоке не может тянуть находку, чьё `resolution` в `artifacts/proofs/core-checks/kernel-findings.json` выглядит закрытым. Словарь закрытия (`CLOSED_FINDING_VOCABULARY`) зашит в код, мутационный тест требовал срабатывания на `F-08` — том самом примере, из-за которого правило появилось (дубль ремонта A11, закрытого выше в PR #47).

## 2. Текущее состояние (факты — замеры, а не версия событий)

Предикат правила (`resolution.trim().toUpperCase().startsWith(marker)`) применён к живому реестру (14 находок, замер 2026-09-16T08:47Z):

| Находка | Начало `resolution` | Видимость правилу |
|---|---|---|
| F-01 | «Решение владельца 2026-09-14 …» | VISIBLE (`РЕШЕНИЕ ВЛАДЕЛЬЦА`) |
| F-02 | «Частично закрыто этим PR …» | **INVISIBLE** |
| F-03 | «Реестр вводит раздельные статусы …» | **INVISIBLE** |
| F-04 | «Исправлено в этом PR …» | VISIBLE (`ИСПРАВЛЕНО`) |
| F-05 | «Граница доверия зафиксирована …» | **INVISIBLE** |
| F-06 | «Исправлено в 0.4.189 …» | VISIBLE (`ИСПРАВЛЕНО`) |
| F-07 | «Исправлено в 0.4.189 …» | VISIBLE (`ИСПРАВЛЕНО`) |
| F-08 | «РЕШЁНО (2026-09-15 …» | VISIBLE (`РЕШЁНО`) |
| F-09…F-14 | (пусто — открыты по построению) | OPEN, тяга разрешена |

Итого: из 8 непустых `resolution` **3 невидимы** (F-02, F-03, F-05) — синтетическая карточка в `ready`, тянущая любую из них, давала **0 нарушений**. Мутационный тест до ремонта — один, на `F-08` (`tools/tpsStandardWork.test.ts`: `title: 'F-08: ремонт A11'`) — то есть на примере-основателе правила.

## 3. Цель

Невидимое должно останавливать, а не проходить: любое непустое `resolution` либо распознано как закрытое, либо явно требует классификации; мутационный тест покрывает **все записи реестра**, а не пример, из которого правило выведено. Зелёный гейт над тягой обязан означать «сверено», а не «не посмотрели».

## 4. Анализ первопричины (5 почему — по фактам замера)

1. Почему F-02/F-03/F-05 невидимы? — Предикат — `startsWith` по словарю, составленному по первым увиденным записям (F-08 «РЕШЁНО…», F-01, F-04, F-06, F-07); формулировки «Частично…», «Реестр вводит…», «Граница доверия…» в словарь не вошли.
2. Почему словарь неполон? — Правило выведено из формы первых увиденных записей, а не из определения закрытости; в реестре нет машиночитаемого `status` (`K-0011` — решение владельца, до сих пор `PROPOSED`).
3. Почему неполнота не вскрылась тестом? — Мутационный тест построен на том же примере (F-08), из которого выведено правило: проверка ловит только основателя. Самоциклирование проверки.
4. Почему самопроверка сошла за контрмеру? — `challenger` карточки `TPS-0009` («как ремонт мог бы выглядеть успешным? — правило срабатывает только на выдуманных данных») был «закрыт» проверкой на живом F-08 — живом, но том же самом: атака требовала независимого свидетельства, а получила повтор примера.
5. Почему это самый опасный класс? — Страж не краснеет, он создаёт видимость защиты: зелёный гейт над тягой F-03 читается как «реестр сверен», хотя сверка слепа. Красный страж виден всем; слепой зелёный — никому.

**Корень (дословно из находки):** правило выведено из формы первых увиденных записей, а мутационный тест построен на том же примере, из которого правило выведено (самоциклирование проверки).

## 5. Контрмеры

| # | Мера | Класс |
|---|---|---|
| 1 | `classifyFindingResolution`: `CLOSED` / `OPEN` / `UNCLASSIFIED`; неклассифицированное непустое `resolution` останавливает карточку кодом `CARD_FINDING_UNCLASSIFIED` с тем же явным выходом через `findingReferenceWaivers`; нормализация Ё/Е (иначе «РЕШЕНО» без точек слепо — поймано новым же тестом) | пока-ёке (fail-safe) |
| 2 | `CARD_FINDING_UNKNOWN` (ссылка на отсутствующий id — опечатка; не освобождается) и `CARD_WAIVER_UNKNOWN_FINDING` (висячий waiver) — тот же класс невидимости в форме ссылки | пока-ёке |
| 3 | Мутационный sweep по живому реестру: каждая находка тянется синтетической карточкой; закрытая обязана дать `ALREADY_CLOSED`, неклассифицированная — `UNCLASSIFIED`, открытая — зелень; тест требует присутствия всех трёх классов, иначе вакуумен | проверка проверяющего |
| 4 | Единый предикат `isLineStoppingEvent` для гейта (`ANDON_OPEN_BLOCKER`), витрины (`renderBoard`) и консольной сводки (`tpsGate`) + тест измеренного согласия трёх рендерингов | устранение дублирования предиката |
| 5 | В стандарт: «мутационный тест не может строиться только на примере, из которого выведено правило» (§5, следствие `K-0007`) | закрепление в стандарте |

## 6. Проверка

- До ремонта (замер предиката по живому реестру): 5 visible / 3 invisible; синтетические карточки на F-02/F-03/F-05 — 0 нарушений.
- После ремонта (замер правилом, те же 8 карточек): 8/8 останавливают — 5 `CARD_FINDING_ALREADY_CLOSED` + 3 `CARD_FINDING_UNCLASSIFIED`; 6 открытых (F-09…F-14) тянутся свободно.
- `npx vitest run tools/tpsStandardWork.test.ts` → 41/41 (4 новых теста: классификация, sweep, waiver/exit для unclassified/unknown, согласие сводки); `npm run tps:gate` → 0; `npm run lint` → 0; сборка и полный `npm test` — в карточке `TPS-0010`.
- Побочный улов: новый тест классификации сразу поймал дыру Ё/Е (`решено` строчными → `РЕШЕНО` ≠ `РЕШЁНО`); закрыта нормализацией в том же предикате.

## 7. Остаточный риск

- Словарь остаётся эвристикой: новая формулировка закрытия даст `UNCLASSIFIED` (стоп, не пропуск) — остаток переведён из слепоты в явную работу. Полное снятие — `K-0011` (`status` в реестре, решение владельца формата).
- Регекс ссылок `F-\d{2}` не ловит lowercase/без-дефиса (латентно); расширение измерено как опасное — даёт ложные срабатывания на hex-хешах вида `6f1ef4e5` в текстах карточек. Оставлен как есть осознанно.
- Про сводку — см. Приложение: исторического факта «сводка раньше печатала неверно» нет (старая версия не запускалась); есть измеренное расхождение предикатов и тест согласия.
