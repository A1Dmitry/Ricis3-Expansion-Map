# A3 — ANDON A-0010: приложение не отображается — dev-сервер Vite отклонял проксированный хост (403)

**Дата:** 2026-09-16 · **Владелец:** агент (автономный цикл RCVAP) · **Процесс:** [`../TOYOTA_TPS_WORKING_SYSTEM.md`](../TOYOTA_TPS_WORKING_SYSTEM.md)
**Андон:** `A-0010` (high) · **Карточка:** `TPS-0011` · **Кайдзен:** `K-0013` · **Потеря:** `M-0014`
**Технический разбор целиком:** [`../../05-evidence/architecture/incident-2026-09-16-preview-not-displaying.md`](../../05-evidence/architecture/incident-2026-09-16-preview-not-displaying.md)

## 1. Фон

Пользователь сообщает: «восстановление работы приложения — оно не отображается». Ветка `main` на 0.4.199: гейты `lint`/`test`/`build` зелёные, деплой Pages `success`, клиентский код при рендере в jsdom даёт полный интерфейс (DOM 374 447 символов, 0 `console.error`). То есть **приложение целое, а не отображается оно только в канале превью**.

## 2. Текущее состояние (факты — замеры, а не версия событий)

- `curl` на localhost → `200`. `curl` с проксированным хостом превью → `403 Blocked request. This host (…) is not allowed.`
- Текст ответа — дословно от Vite (`hostValidationMiddleware`), и он приходит **раньше** SPA-мидлвари: документ и модули отклоняются одинаково, клиентских ошибок не существует.
- Причина в конфигурации: `allowedHosts: process.env.VITE_ALLOWED_HOSTS === "true" ? true : undefined` — opt-in-гейт; переменную не выставляет ни платформа, ни скрипты, ни `.env*`, поэтому эффективно остаётся дефолт Vite `[]`.
- Дефект внесён апгрейдом тулчейна `e5bd034` (2026-08-17, `vite ^5.3.4` → `^8.2.1`): проверка хоста появилась в Vite 6.0.9+/5.4.12+/4.5.6+ (DNS-rebinding), в 5.3.4 её нет. С этого дня превью в песочнице не работало всегда.
- Обход графа модулей dev-сервера (после ремонта): 208/208 → `200`. Модули исправны — испорчен был вход.

## 3. Цель

Приложение обязано доходить до браузера через штатный проксированный хост площадки **без внешних переменных и без ручных действий**, а класс дефекта обязан ловиться машиной: проба, которая не может покраснеть, защитой не считается.

## 4. Анализ первопричины (5 почему — по фактам замера)

1. **Почему превью пустое?** — Vite отдаёт `403` до SPA-мидлвари: браузер не получает ни документа, ни модулей.
2. **Почему тесты этого не видели?** — Ни один прогон не поднимает dev-сервер и не делает HTTP-запрос с чужим `Host`; jsdom-тесты не проходят транспортный слой, а `vitest` не монтирует Vite-мидлварь приложения.
3. **Почему это не видно в build/деплое?** — Другой канал: `vite build` не читает `server.*`, Pages получает статику, `npm start` отдаёт `dist/` без Vite. Гейты зелёные при неработающем превью.
4. **Почему «ремонт» из аудита (PR #55) не помог?** — Он включил `allowedHosts` за флагом, который никто не выставляет, и записал это как меру «по умолчанию поведение неизменно». Мера, требующая внешнего действия, которое не выполняется, — не контрмера.
5. **Почему дефект появился?** — Апгрейд тулчейна без проверки транспортного контракта: 2026-08-17 зависимость поднята с `vite ^5.3.4` на `^8.2.1`, где проверка хоста существует и по умолчанию запрещает всё, кроме localhost/IP.

**Корень:** транспортный контракт dev-канала (в каком окружении и под каким `Host` реально работает приложение) не был ни задан явно, ни покрыт проверкой; поэтому смена дефолта в зависимости прошла молча, а «зелёная» линия проверок этот канал не пересекала.

## 5. Контрмеры

| # | Мера | Класс |
|---|---|---|
| 1 | Единая политика `resolveDevAllowedHosts()` в `server/devHostPolicy.ts`; дефолт — проксированные хосты разрешены, сужение возможно явно (`false` — только localhost/IP, список — явные суффиксы) | устранение неявного дефолта |
| 2 | Политика **opt-out** (а не opt-in): `npm run dev` работает в превью без внешних переменных | пока-ёке по построению |
| 3 | Та же политика подключена к `server.allowedHosts` и `preview.allowedHosts` в `vite.config.ts` (второй и третий вход Vite) | ёкотэн |
| 4 | `server/devHostPolicy.test.ts`: реальная HTTP-проба через Vite-мидлварь с хостом превью **и** контрольная проба строгого режима (`403`) | проверка, которая умеет краснеть |
| 5 | Стартовый лог политики в dev-сервере + документирование переменной и симптома в `.env.example` и `README.md` | наблюдаемость вместо догадок |

## 6. Проверка

- До ремонта: `curl -H 'Host: <preview-host>' localhost:3000/` → `403`, тело — `Blocked request…`.
- После ремонта: тот же запрос → `200`; `/src/main.tsx` → `200` (ESM-модуль); обход графа модулей `208/208 → 200`.
- `npx vitest run server/devHostPolicy.test.ts` → **10/10** (включая невакуумность: строгий режим обязан дать `403`).
- `npx tsc --noEmit` → `0`.
- Полный набор гейт-команд (`release:check`, `lint`, `npm test`, `build`, `tps:gate`) — фактические прогоны в карточке `TPS-0011`.

## 7. Остаточный риск

- `allowedHosts: true` в dev **отключает** защиту от DNS-rebinding для dev-сервера: принято осознанно (dev всегда за доверенным прокси площадки), узкая настройка сохранена и документирована.
- Опубликованный сайт (GitHub Pages) этим ремонтом не проверялся: из песочницы внешний HTTPS-эгресс к `a1dmitry.github.io` недоступен (TLS-ошибка соединения). Утверждения о доступности Pages в свидетельство не входят.
- Транспортный канал по-прежнему не проверяется в CI: страж локален (юнит+HTTP-проба внутри vitest). Перенос пробы в CI-шаг — кандидат в кайдзен, пока не сделан.
