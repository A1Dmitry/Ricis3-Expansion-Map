# Ворота трассировки исполнителя (execution traceability gates)

Статус: нормативный документ уровня исполнения (governance). Не является математической
аксиомой RICIS‑III: документ не изменяет ядро, аксиомы, манифест неизменности
([`RICIS_IMMUTABILITY_MANIFEST.md`](RICIS_IMMUTABILITY_MANIFEST.md)) и не вправе менять
научные статусы. Он добавляет только правила идентификации исполнителя в GitHub-истории и
ворота их проверки, не дублируя [RCVAP-протокол](RCVAP_AUTONOMOUS_ANTI_TUKHTA_AGILE_PROTOCOL.md),
[`WORK_PATTERNS.md`](WORK_PATTERNS.md) и
[`RICIS_EXTERNAL_EXECUTOR_PROTOCOL.md`](RICIS_EXTERNAL_EXECUTOR_PROTOCOL.md), а дополняя их
на уровне git-трассировки.

## §1. Ключ исполнителя

1. Исполнитель идентифицируется в репозитории **только** детерминированным непрозрачным
   ключом: `executor_key = SHA-256(canonical_identity)`, где `canonical_identity` — полная
   каноническая идентичность среды исполнения текущего исполнителя (с суффиксом версии,
   если версия доступна отдельно).
2. Регистрация текущего ключа — файл
   [`EXECUTOR_KEY.md`](EXECUTOR_KEY.md) (строго канонический шаблон: `executor_key`,
   `created_at`, `purpose`).
3. Приватность: исходная идентичность (имя исполнителя, модели, провайдера, версия) **никогда
   не записывается** в репозиторий — ни в этот файл, ни в коммиты, ни в отчёты ворот. Хранится
   и фигурирует только сам 64-символьный hex-ключ.
4. Стабильность: ключ неизменен, пока неизменна каноническая идентичность исполнителя, и
   обязан смениться при её смене. Новая регистрация перезаписывает `EXECUTOR_KEY.md`; прежние
   регистрации сохраняются историей git и остаются валидными для коммитов своего периода
   (ворота G1 проверяют ключ «на момент коммита»).

## §2. Правило заголовка коммита

Перед каждым коммитом исполнитель **обязан** записать в заголовок (первую строку
commit-сообщения) пару «исполнитель : ключ»:

```
исполнитель : <ключ>
```

- `<ключ>` — ровно 64 строчных hex-символа, зарегистрированных в `EXECUTOR_KEY.md` на момент
  коммита;
- после ключа допускается краткое уточнение; подробное описание — в теле сообщения;
- форма: `^исполнитель : [0-9a-f]{64}( .*)?$`.

Коммит без такого заголовка (нет префикса или ключ искажён) неатрибутируем: ворота G1/G3
отклоняют его с **обязательным текстом исключения** (константа
`KEYLESS_COMMIT_EXCEPTION_TEXT` в
[`tools/executorTraceability.ts`](../../tools/executorTraceability.ts)):

> исключение: коммит без ключа отклонён — надо создать ключ по вышеописанному протоколу
> (§1–§2, регистрация — `EXECUTOR_KEY.md`), а лучше еще и пройти обучение — обязательное
> изучение всей документации (перечень — `MANDATORY_STUDY_DOCUMENTS` и отчёт ворот G2).

## §3. Ворота

### G1 — ворота заголовков (обязательные, CI)

`npm run executor:gate -- --check-headers [--base origin/main]`
(шаг `pr-verify.yml`; реализация — [`scripts/executorGate.ts`](../../scripts/executorGate.ts))

- каждый коммит диапазона `<base>..HEAD` обязан иметь валидный заголовок по §2;
- ключ из заголовка обязан совпадать с ключом, зарегистрированным в `EXECUTOR_KEY.md`
  **ровно на этот коммит** (`git show <sha>:docs/00-governance/EXECUTOR_KEY.md`);
- отказ ворот (exit 1) — андон: PR не может быть принят, пока заголовки не приведены к
  правилу §2 (amend/rebase).

### G2 — ворота функциональной целостности по истории GitHub (форензика)

Запускается оператором, когда по истории GitHub обнаружен сломанный функционал:

```
npm run executor:gate -- --forensics <хороший-ref> [--policy restudy|reject] [-- <тестовая команда>]
```

- ворота прогоняют `git bisect run` по истории (по умолчанию `npm test`) и находят **первый**
  коммит, сломавший функционал;
- из заголовка этого коммита извлекается ключ исполнителя (§2), после чего выносится вердикт:
  - `MANDATORY_DOCUMENTATION_STUDY` (policy `restudy`, по умолчанию): исполнитель с этим
    ключом **принудительно направляется на изучение всей документации** (полный перечень —
    в отчёте ворот: `AGENTS.md`, RCVAP-протокол, work patterns, TPS-система, манифест
    неизменности, семантическая авторитетность, внешний исполнительский протокол,
    настоящий документ, канонический документ RICIS‑III); исправляющий коммит обязан нести
    trailer `documentation-restudy: <ключ>` как подтверждение изучения;
  - `REJECT` (policy `reject`, либо нарушитель неатрибутируем): **немедленный отказ** — вклад
    отклоняется, в отчёте ворот фиксируется минус надёжности ключа; повторный приём вкладов
    этого ключа — только после полного изучения документации и повторной проверки ворот.

### G3 — локальный хук `commit-msg` (вспомогательный)

`hooks/commit-msg` отклоняет локальный коммит без ключа ещё до его создания — с тем же
обязательным текстом исключения по §2 (создать ключ по протоколу, а лучше еще и пройти
обучение). Активация:

```
git config core.hooksPath hooks
```

Обход хука (`--no-verify`) правомерен только технически: обязательные ворота — CI (G1), и они
поймают нарушение на PR.

## §4. Границы ответственности

- Ворота проверяют только трассировку исполнения (§1–§2) и целостность функционала по
  истории GitHub; они не изменяют математические аксиомы, kernel-логику, архитектуру,
  научные статусы и не отменяют `tps:gate` / `pr-verify` — добавляются к ним.
- Форензика G2 фиксирует факт и виновника по истории GitHub; решение о применении
  `restudy`/`reject` и о повторном приёме исполнителя остаётся за мейнтейнером.
