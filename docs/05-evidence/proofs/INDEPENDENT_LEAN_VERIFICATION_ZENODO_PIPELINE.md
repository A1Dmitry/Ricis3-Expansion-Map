# RICIS-III Independent Lean Verification and Zenodo Evidence Pipeline

## 1. Executive Overview & Objective

This document formalizes the reproducible, anti-tukhta evidence pipeline for RICIS-III formal proofs:

```text
RICIS Task Definition
       ↓
Lean Source / Proof Artifact
       ↓
Local Lean 4.33.1 Kernel Check (Level 1)
       ↓ PASS
Independent External Verifier Check (Level 2)
       ↓ PASS
Cryptographic Hash Binding (SHA-256) & Git Commit
       ↓
Canonical Evidence Manifest
       ↓
Zenodo Archival Deposition & Immutable Bundle (Level 3)
       ↓
Permanent Version DOI (10.5281/zenodo.XXXXX)
```

The resulting DOI permanently identifies the exact archived evidence corresponding to the verified proof.

---

## 2. Research on External Lean Verification Services & Tooling

To satisfy the requirement of **actual independent Lean kernel checking** (excluding LLM evaluations), the following systems and architectures were researched:

| Service / Tooling | Lean Version Support | Mathlib Support | Verification Mechanism | Automation / API | Suitability for RICIS Evidence |
|---|---|---|---|---|---|
| **Lean 4 Official Toolchain (`lean +4.33.1`) via isolated runner** | Pinned (4.33.1) | Full via lake / Mathlib cache | Native C++ Lean kernel execution (`#print axioms`) | CLI / CI subprocess | **Primary Local & Container Verifier** |
| **Lean 4 Web / Community Server** | Dynamic / pinned | Limited | WebSocket / JSON-RPC compilation server | REST / WebSocket API | Secondary / Interactive |
| **Independent External Container Runner (GitHub Actions / GitLab / Dedicated VM)** | Exact pinned `elan` toolchain | Full | Independent ephemeral runner with clean environment | GitHub REST API / Webhooks | **Authoritative Independent Verifier (Level 2)** |
| **LLM-based Provers / Evaluators** | N/A | N/A | Probabilistic token generation | REST API | **STRICTLY REJECTED (TUKHTA)** |

### Strict Anti-Tukhta Invariant
No statement generated by an LLM (e.g. `"proof verified"`) is ever accepted as proof verification. Verification status MUST originate exclusively from compiler exit code `0`, `#print axioms` output devoid of `sorryAx`, and cryptographically matched source hashes.

## 3. The 3-Level Verification Hierarchy

```text
   Level 1: LOCAL VERIFICATION
   • Compiler: lean +4.33.1 (pinned via elan)
   • Status: LOCAL_VERIFIED
   • Check: Exit code 0, no sorryAx, AST integrity

   Level 2: INDEPENDENT VERIFICATION
   • Verifier: External isolated runner / service
   • Status: INDEPENDENTLY_VERIFIED
   • Check: Exact environment match, no sorryAx, output hash

   Level 3: ARCHIVED EVIDENCE
   • Repository: Zenodo REST API v2 (Deposition & Records)
   • Status: ARCHIVED
   • Output: Concept DOI & Version DOI, immutable SHA-256 package
```

---

## 4. Verification States & Gate Transitions

| State | Prerequisites | Allowed Actions |
|---|---|---|
| `UNVERIFIED` | Raw submission | Run Local Verifier |
| `LOCAL_VERIFIED` | Local exit code 0, no sorryAx, valid syntax | Run Independent External Verifier |
| `INDEPENDENTLY_VERIFIED` | Local PASS + Independent PASS + Environment match | Eligible for Zenodo Archival |
| `ARCHIVED` | Independent PASS + Hash Match + Zenodo Deposition published | Cite Version DOI in research & publications |

## 6. What a DOI Proves vs What it Does NOT Prove

- **What a Zenodo DOI Proves**:
  1. Cryptographic and archival identity of the exact source file and manifest package at a fixed timestamp.
  2. Public availability and immutability of the deposition in CERN/Zenodo long-term storage.
  3. Association with declared author ORCID and Git commit metadata.

- **What a Zenodo DOI Does NOT Prove**:
  1. A DOI by itself does not constitute mathematical truth.
  2. The mathematical correctness is established exclusively by the Lean kernel verification log (`#print axioms`, `exit code 0`, 0 `sorryAx`).

## 7. How Third Parties Reproduce the Verification

To reproduce any verified proof independently:

1. Download the evidence package from Zenodo:
   ```bash
   curl -O https://zenodo.org/record/<RECORD_ID>/files/<BUNDLE_NAME>.json
   ```
2. Verify the SHA-256 checksum:
   ```bash
   sha256sum <BUNDLE_NAME>.json
   ```
3. Extract `verifiedSourceCode` and save as `proof.lean`.
4. Run Lean 4.33.1 kernel check:
   ```bash
   elan run leanprover/lean4:v4.33.1 lean proof.lean
   ```
5. Confirm exit code is 0 and `#print axioms` output contains no `sorryAx`.
