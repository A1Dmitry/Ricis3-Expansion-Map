## 3. Находки (зафиксированы в реестре, не замалчиваются)

### F-09 (HIGH) — метрика вместо исходной задачи

```
ricis_eval_general S := if S.m ≥ S.n then (let k := S.m - S.n; if k = 0 then N_tilde a / D_tilde a else 0) else 0
theorem ricis_general_resolution (S) : S.m ≥ S.n → ricis_eval_general S = (if S.m = S.n then N_tilde a / D_tilde a else 0)
```

Утверждение теоремы — **развёрнутое определение той же функции**; доказательство — `intro`,
`dsimp only [ricis_eval_general]`, `by_cases`, `omega`, `simp`. Сверка тел доказательств: имена
`ax_A4_general`, `ax_SP1_general`, `ricis_reduce` не встречаются ни в одном доказательстве файла
(только в собственных объявлениях). Формальная метрика «теорема доказана, ядро примет» выполняется
при недоказанной содержательной задаче — класс ТУФТЫ по RCVAP (результат удовлетворяет формальной
метрике, но не решает исходную задачу).

### F-10 (HIGH) — необъявленная граница доверия

* `axiom ax_A4_general` и `axiom ax_SP1_general` — доверенные входы. §7 требует видимой границы
  доверия; в исходнике её нет (ни маркировки, ни ссылки на evidence). Зафиксирована снаружи:
  `declaredAxioms`, плюс эпилог прогона печатает `#print axioms` и для контрактов.
* Заголовок «(ФИНАЛЬНАЯ ВЕРСИЯ 2)» и имя `ricis_equals_classical_limit` создают впечатление
  доказанного совпадения с классическим пределом. Никакое предельное выражение (`lim`, Лопиталь,
  Коши) в файле не определено и не выводится; P1 RICIS прямо запрещает пределы внутри
  `Resolve_RICIS`. Теорема — прямая ссылка на предыдущую, без какого-либо предельного содержания.

### F-11 (MEDIUM) — разрыв «редукция ↔ вычисление», сингулярность не предъявлена

`ricis_reduce` — единственное место, где выполняется сокращение `(z-a)^min(m,n)` и строится
редуцированное выражение — не используется ни одной теоремой. Ни одна теорема не связывает
`ricis_reduce S` со значением `ricis_eval_general S` (например, определённость редуцированного
выражения в точке `a`). Условия `N a = 0 ∧ D a = 0` не утверждаются ни для общего случая, ни в
форме `RicisExpr`: объекта разрешения (индексированного нуля) в артефакте нет.

### F-12 (MEDIUM) — недостоверное основание `REQUIRES_CORE_LEAN` для 14 Mathlib-артефактов

Основание «no pinned prebuilt Mathlib fits a standard runner» (README 0.4.189) верно только для
сборки Mathlib из исходников. Ремонт: job `mathlib-kernel-check` с prebuilt oleans
(`lake exe cache get`) на тулчейне закреплённой ревизии Mathlib. Ни один статус при этом не
повышается автоматически: прогон идёт только для файлов из явного allowlist `MATHLIB_ARTIFACTS`.

## 4. Статический аудит (SUPERSEDED_BY_KERNEL_RUN — сохранён как поправленный прогноз)

Ниже — **чтение исходника**, а не результат компиляции: так выглядел прогноз до прогона
(каналы установки Lean-тулчейна в среде агента недоступны). Прогноз **опровергнут/уточнён** прогоном
34950902412 (§4.0): пункт 1 опровергнут, пункты 2–3 не понадобились (файл скомпилировался),
пункт 4 подтверждён как warning. Блок сохранён без правки как свидетельство точности
предсказаний — именно поэтому он и не мог служить статусом.

1. ~~**Область видимости тактики `omega`.**~~ **ОПРОВЕРГНУТО прогоном:** Тактика используется в четырёх местах
   (`ricis_general_resolution` ×2, `specific_case_from_general` ×1 и в блоке сборки конъюнктов),
   но ни один из трёх импортов файла — `Mathlib.Data.Complex.Basic`, `Mathlib.Tactic.Ring`,
   `Mathlib.Data.Nat.Basic` — её не объявляет. Где именно живёт `omega` в Mathlib 4.33
   (`Mathlib.Tactic.Linarith` / `Mathlib.Tactic.Order` / `Mathlib.Tactic`), проверяется прогоном:
   предсказание — ошибка «unknown tactic 'omega'», возможен каскад `sorryAx`.
2. **`intro` по `let`-биндингам.** Цель `specific_case_from_general` начинается цепочкой из семи
   `let`-биндингов, а `intro N D a m n N_tilde D_tilde` вводит семь имён. Zeta-редукция `intro` по
   `let` определяет, останутся ли в цели конкретные значения (`m = n = 1`, `a = -i`) или
   произвольные переменные. Во втором случае цели `∀ z, N z = (z - a)^m * N_tilde z`, `m ≥ n` и
   равенство `-2 * I` недоказуемы, и доказательство обрывается на `exact hN` / `omega`.
3. **`simp` с let-именами.** Финальный блок `simp [h_mn, N_tilde, D_tilde, a, m, n]` опирается на
   локальные `let`-имена как на simp-аргументы: при иной форме цели (свободные переменные вместо
   `let`-значений) это недопустимый simp-аргумент.
4. **Возможный избыточный шаг.** `simp [h_k_ne_zero]` в ветви `m ≠ n` способен закрыть цель
   целиком; следующий за ним `omega` в этом случае применяется при отсутствии целей — класс дефекта
   F-06 («No goals to be solved»), не влияющий на утверждение, но роняющий компиляцию.
5. **Байтовый нюанс (не влияет на семантику).** Последняя строка файла содержит текст инструкции
   владельца внутри строки комментария; сохранена без изменений (§7).

**Исход прогона: см. §4.0 (прогноз был помечен UNKNOWN и оставался не-статусом).** Прежняя формулировка: Ни один из пунктов выше не является основанием для
регистрации ожидаемого отказа (`ciPolicy.mathlibExpectedFailures` оставлен пустым до фактического
прогона: прогноз — не факт).
