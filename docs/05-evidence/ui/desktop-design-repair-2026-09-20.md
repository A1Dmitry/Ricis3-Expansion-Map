# Desktop UI: разбор ошибки и исправление — 0.4.221

AUDITOR: SELF (same-pipeline)

> Исторический отчёт 0.4.221 до синхронизации с GitHub. Текущее объединение и его проверки: [0.4.224](github-integration-0.4.224.md).

## 1. ORIGINAL GOAL
Исследовать практики desktop UI, сопоставить с деградацией интерфейса 0.4.220 и исправить причины. Сохранить классическую текстовую строку меню; все действия задачи — в существующем hamburger заголовка, без дополнительного меню в теле и заголовка «Действия задачи».

## 2. RESULT
Введено разделение семантики: IconButton — компактная команда панели; ContentButton — видимая подпись действия/раскрывающегося раздела; SelectionCard — целиком выбираемая карточка; ContentLink — текстовая ссылка. Исправлены боковые панели, иерархия карточки задачи, размещение команд, высота рабочей области и переносы узкого интерфейса. Версия синхронизирована штатным sync:version.

### Рекомендация → нарушение → исправление
| Источник и практика | Что было неверно | Изменение |
|---|---|---|
| [Microsoft: Toolbars](https://learn.microsoft.com/en-us/windows/win32/uxguide/cmd-toolbars): меню с текстом, toolbar для частых команд | Единый icon-only контракт применялся к меню, навигации, заголовкам и действиям | Текстовые menus/menubar сохранены; текстовые действия отделены от компактных иконок |
| [NNG: Icon usability](https://www.nngroup.com/articles/icon-usability/): большинство иконок неоднозначны, подписи улучшают распознавание | Hover был единственным способом узнать смысл научной команды и заголовка раздела | Постоянные подписи у команд, вкладок, ссылок и карточек; подсказки дополняют оставшиеся иконки |
| [Microsoft: Command bar](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/command-bar): разделение первичных и вторичных команд, читаемые подписи overflow | Дубли команд и одинаковое оформление разных типов элементов | Убран дубль Share; действия задачи сгруппированы в одном меню заголовка |
| [NNG: Accordions on desktop](https://www.nngroup.com/articles/accordions-on-desktop/), [Accordion icons](https://www.nngroup.com/articles/accordion-icons/): описательный заголовок и индикатор раскрытия | Заголовок превращался в маленькую иконку; скрытие через checkbox/max-height не отражало семантику | Вся строка — кнопка с подписью, caret, aria-expanded/aria-controls; скрытая панель использует hidden |
| [Microsoft: Toolbars](https://learn.microsoft.com/en-us/windows/win32/uxguide/cmd-toolbars): беречь рабочую область | Широкие пустые панели с квадратными кнопками; заголовок задачи конкурировал с командами | Адаптивные колонки, компактные подписанные действия, отдельная строка команд над заголовком задачи |
| [NNG: Menu design](https://www.nngroup.com/articles/menu-design/): ясные текстовые варианты | Иконка заменяла содержимое выбора | Восстановлены подписи и целая область выбора; штатные disabled/callback/ref сохранены |

Размеры 32 px для desktop-иконок и 44 px для coarse pointer — проектное решение, а не заявление, что все источники требуют именно эти числа. Фиксированный квадрат не применяется к текстовым действиям.

## 3. VERIFICATION
- `npm run lint`: PASS (TypeScript).
- `npx vitest run src/ui`: 57 файлов, 270 тестов PASS.
- `npm run build`: PASS, включая release consistency checks.
- `git diff --check`: PASS.
- Chromium/Playwright: 1440×1000 и 1100×800 — раскрытие мышью и Enter, действительно скрытая панель, один trigger меню задачи в заголовке, отсутствие tooltip поверх открытого меню, Escape закрывает меню, отсутствие горизонтального overflow документа, footer внутри viewport.
- 390×844: отсутствие горизонтального overflow документа, визуальная проверка переносов. Desktop footer здесь не рендерится; сценарий не требует его наличия на mobile.
- Просмотр снимков выявил отдельную ошибку: кнопка «3D-карту» сжималась в вертикальную надпись в узкой центральной колонке. Исправлен перенос всей строки переключателей; снимки и lint/UI/build повторены после исправления.

## 4. POSITIVE RESULTS
Видны названия разделов, кнопок и выбранной задачи; карточки выбираются целиком. Длинный заголовок задачи переносится отдельно от hamburger. Верхняя строка имеет текстовые пункты. Footer не уходит за нижнюю границу desktop окна. Закрытый accordion не оставляет интерактивное содержимое видимым.

## 5. NEGATIVE RESULTS
Снимок с software WebGL не получен: Chromium вернул `Page.captureScreenshot: Unable to capture screenshot`. При этом DOM содержал canvas, а footer был на границе viewport. Это не подтверждает корректность 3D-сцены. Прилагаемые снимки выполнены с отключённым WebGL и показывают штатный доступный 2D-режим. Предупреждение build о `import.meta` в CJS (`server/zenodoHttpAdapter.ts:67`) осталось. Есть существующие React act warnings в UI-тестах. Полный проектный suite на финальном состоянии не запускался; его прохождение не заявляется.

## 6. TUKHTA FOUND
Предыдущая массовая замена элементов на иконки ошибочно выдавала унификацию примитива и зелёную проверку инвентаря за улучшение UI. Она скрывала информацию, ради которой существуют заголовки, карточки и навигация. Проверка одного dropdown не могла подтвердить исправление всей страницы.

## 7. ROOT CAUSES
Смешение текстовых и иконковых контролов; принудительная геометрия в общем CSS; скрытые подписи вместо визуальной иерархии; разделение карточки на текст и маленькую кнопку; вложенная viewport-высота внутри рабочей области; непереносимая flex-строка переключателей.

## 8. REPAIRS
ContentButton/SelectionCard/ContentLink, исправленный ActionButton; удалён IconChoice; semantic accordion в Map3D; адаптивные ширины колонок; единый заголовок задачи и сворачиваемые технические идентификаторы; h-full/min-h-0 вместо вложенного h-screen; собственный scroll длинных applet; подавление tooltip при открытии меню. Добавлены тесты видимого контента, ref, disabled/callback, native links и целиком кликабельной карточки. Старые copy-тесты теперь ищут видимый текст, сохраняя проверки callback и disabled.

## 9. REMAINING RISKS
Нет внешнего рецензента. Не подтверждены реальная GPU-сцена и все диалоги/апплеты/локали в браузере. Mobile проверен на smoke-уровне, не полным проходом. Плотность подписей узлов самой 2D-карты этим изменением не переработана. Отсутствие overflow документа само по себе недостаточно: поэтому снимки также просмотрены вручную в рамках того же пайплайна.
