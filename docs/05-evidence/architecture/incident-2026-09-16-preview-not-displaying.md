# Инцидент 2026-09-16: «приложение не отображается» — dev-сервер Vite отклонял проксированный хост (HTTP 403)

**Дата:** 2026-09-16 · **Версия до ремонта:** 0.4.199 · **После:** 0.4.200
**Тип:** инцидент доступности (transport уровня `npm run dev`), **не** научный и **не** proof-слой.
**Андон:** `A-0010` · **Карточка:** `TPS-0011` · **Кайдзен:** `K-0013` · **A3:** [`../../00-governance/tps/A3-ANDON-0010.md`](../../00-governance/tps/A3-ANDON-0010.md)
**Статус:** закрыт ремонтом + regression-тестами; воспроизведение «до/после» зафиксировано ниже.

---

## 1. Симптом

Пользователь открывает живое превью приложения (проксированная площадка, `https://<port>-<sandbox-id>.e2b.app`) и **не видит приложения**. Ни спиннера загрузки, ни интерфейса, ни клиентской ошибки в интерфейсе — экран пустой/чужой текст. `npm run dev` при этом печатает только `Server running on http://localhost:3000`, то есть сервер считает, что запустился нормально.

## 2. Факт (дословно, без пересказа)

Платформа превью сообщает о блокирующем ответе сразу при запуске процесса:

```text
Port 3000 REJECTS the user's preview host "3000-i1nfmt1owr5psuyk5cyv4.e2b.app"
(HTTP 403: Blocked request. This host ("3000-i1nfmt1owr5psuyk5cyv4.e2b.app") is not allowed.
 To allow this host, add "3000-i1nfmt1owr5psuyk5cyv4.e2b.app" to `server.allowedHosts` …)
```

Ответ на `curl` с хостом превью (localhost при этом отвечает 200):

```console
$ curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3000/
200

$ curl -s -i -H 'Host: 3000-i1nfmt1owr5psuyk5cyv4.e2b.app' http://localhost:3000/ | head -12
HTTP/1.1 403 Forbidden
X-Powered-By: Express
Content-Type: text/plain

Blocked request. This host ("3000-i1nfmt1owr5psuyk5cyv4.e2b.app") is not allowed.
To allow this host, add "3000-i1nfmt1owr5psuyk5cyv4.e2b.app" to `server.allowedHosts` in vite.config.js.
```

## 3. Первопричина

**Проверка хоста в dev-сервере Vite (`server.allowedHosts`) отклоняет проксированный хост превью, и делает это до SPA-мидлвари.** Обработчик стоит первым в цепочке Vite-мидлвари, поэтому отклоняется **не только документ, но и каждый запрос модуля**: ни один байт кода приложения до браузера не доходит, и клиентской ошибки, которую можно было бы увидеть в консоли, не существует — приложение просто не запускалось.

Механика (по установленному `vite@8.2.1`, `node_modules/vite/dist/node/chunks/node.js`):

| Место | Факт |
| :-- | :-- |
| `:26661` | `allowedHosts` по умолчанию `[]` — то есть «ничего не разрешено сверх встроенных исключений» |
| `:26556` | `if (allowedHosts !== true && !serverConfig.https) middlewares.use(hostValidationMiddleware(...))` — проверка ставится и в `middlewareMode`, то есть в схему `server.ts`, где Vite смонтирован внутрь Express |
| `:17402` | `isHostAllowedInternal` без настройки пропускает только `localhost`, `*.localhost`, IP-литералы и `file:`/`-extension:` — проксированный домен не попадает ни в одну категорию |
| `:17445` | при промахе — `403` с текстом `Blocked request…`, без вызова следующего мидлвара |

Настройка проекта до ремонта (`server.ts`) была **opt-in** и потому не действовала:

```ts
// было (фактически: «разрешить проксированный хост, только если кто-то выставит
// переменную, которой в песочнице/превью никто не выставляет» → остаётся undefined → [])
allowedHosts: process.env.VITE_ALLOWED_HOSTS === "true" ? true : undefined,
```

## 4. Почему это не поймали раньше (5 почему)

1. **Почему превью пустое?** — Потому что 403 отдаётся до SPA-мидлвари: браузер не получает ни HTML, ни модулей.
2. **Почему тесты этого не видели?** — Потому что ни один прогон в репозитории не поднимал dev-сервер и не делал HTTP-запрос с проксированным `Host`: 2000+ тестов работают в jsdom и не проходят через транспортный слой; `vitest` вообще не монтирует Vite-мидлварь приложения. Гейт-команды `lint`/`test`/`build` зелёные **при полностью неработающем превью**.
3. **Почему build и деплой это не показывают?** — Потому что продовый путь другой: GitHub Pages получает результат `vite build`, где конфигурация `server.*` не участвует, а `npm start` отдаёт `dist/` прямо из Express без Vite. Инцидент жил **только** в dev/превью-канале.
4. **Почему «ремонт» из аудита 2026-09-16 не помог?** — Он добавил тот же `allowedHosts`, но за флагом `VITE_ALLOWED_HOSTS === "true"` и с формулировкой «по умолчанию поведение неизменно». Переменную не выставляет ни платформа, ни `.env*`, ни скрипты: эффект остался нулевым, дефект был зафиксирован как «решённый» инструментально, хотя фактически не изменён. Работа, требующая внешнего действия, которое не выполняется, — это не контрмера, а её описание.
5. **Почему дефект вообще появился?** — Он внесён апгрейдом тулчейна: `e5bd034` (2026-08-17, «fix: synchronize npm dependencies and secure build toolchain») поднял `vite` с `^5.3.4` до `^8.2.1`. Проверка хоста появилась в Vite **6.0.9+/5.4.12+/4.5.6+** как защита от DNS-rebinding ([обсуждение vitejs/vite#19426](https://github.com/vitejs/vite/discussions/19426), advisory GHSA-vg6x-rcgg-rjx6); в 5.3.4 её нет. То есть с 2026-08-17 превью в песочнице не работало **всегда**, а «поломка» не была замечена, потому что заметить её можно только глазами в браузере или HTTP-пробой с чужим `Host`.

## 5. Временная линия (по коммитам, а не по воспоминаниям)

| Коммит / дата | Что с `allowedHosts` | Что видит пользователь превью |
| :-- | :-- | :-- |
| … → `d739d8b` (2026-08-14), `vite ^5.3.4` | поля нет; в Vite 5.3.4 проверки хоста нет | приложение работает |
| **`e5bd034` (2026-08-17), `vite ^8.2.1`** | поля нет → `[]` | **403, пустое превью** (с этого дня) |
| `47fbb6f` (2026-09-16, аудит, PR #55) | добавлен opt-in `VITE_ALLOWED_HOSTS === "true" ? true : undefined` | 403 без изменений (переменная не выставлена) |
| `91b43b9`, `3eca250` (PR #56, `main` HEAD) | строка перенесена без изменений | 403 без изменений |

Отдельная сторона того же факта: **в репозитории нет ни одной документированной точки входа, где dev-сервер проверяется как транспорт** — ни в `pr-verify.yml`, ни в `deploy-pages.yml`. Статус «приложение работает» опирался на build, который этот канал не покрывает.

## 6. Отброшенные гипотезы (и чем именно отброшены)

| Гипотеза | Проверка | Результат |
| :-- | :-- | :-- |
| Ошибка типов/сборки клиента | `npx tsc --noEmit` → exit 0; `vite build` → успешно, 86 ассетов | отклонена |
| Сломанный деплой Pages | workflow `Deploy to GitHub Pages` на `3eca250` → `success` | отклонена (и это другой канал) |
| Клиентский краш/пустой рендер | реальный `App` (без моков ленивых экранов) отрендерен в jsdom: DOM 374 447 символов, полный рабочий стол `Файл/Вид/Кинематика/…`, `0` `console.error` | отклонена |
| Вечная гидратация IndexedDB | интерфейс появляется после гидратации (наблюдалось ~2 с; в сторе есть 2500 мс guard-фолбэк) | отклонена |
| Битые модули в dev-графе | обход графа модулей через dev-сервер: **208/208 запросов → 200**, ни одного 4xx/5xx | отклонена |
| Сеть/порт превью | платформа достучалась до процесса и получила **ответ приложения** (403 от Vite), то есть проксирование работало | отклонена |

Итог: единственная измеренная причина — проверка хоста Vite. Всё остальное либо не участвует в этом канале, либо работает.

## 9. Границы доверия (что ремонт **не** утверждает)

- `allowedHosts: true` в dev **отключает** защиту от DNS-rebinding для dev-сервера. Это осознанное решение для среды, где dev-сервер по определению стоит за доверенным прокси площадки; возможность сузить сохранена и документирована: `VITE_ALLOWED_HOSTS=false` (только localhost/IP) или `VITE_ALLOWED_HOSTS=.e2b.app,foo.test` (явные суффиксы).
- Продовый периметр не расширяется: `vite build` не читает `server.*`/`preview.*`, а `npm start` отдаёт статику из Express вообще без Vite. Опубликованный сайт (Pages) этим изменением не затронут — его доступность здесь **не проверялась** и не подтверждается (из песочницы внешний HTTPS-эгресс к `a1dmitry.github.io` недоступен: `curl` → ошибка TLS-соединения; это ограничение среды, а не факт о сайте).
- Ремонт ничего не говорит о содержательных статусах RICIS, доказательствах, `trustStatus` узлов и Lean-артефактах.

## 10. Ёкотэн (горизонтальный разнос того же класса)

| Цель | Что проверено | Итог |
| :-- | :-- | :-- |
