## 3. Итог по классам

- **Закрывается принятыми P1–P7 (при строгой реализации):** R2 (по пути, не по словам), R3 (allowlist под владельцем), R5 (сверка sha своего файла), R9, R12.
- **Не закрывается P1–P7 — нужна доработка:**
  - **R1** — ужесточить `AUDITOR_PATTERN`: `EXTERNAL` обязан содержать ссылку на runId реестра или URL/DOI, и запрещены токены `self|same|агент|session` (лексика — слабо; лучше обязательное поле `evidenceRef`).
  - **R4/R8** — независимость и маркер не могут быть **входными полями**; они **выводятся** из типа evidence (kernel run в CI → I2; иначе I0). Это заменяет P2 и P4 одним правилом: *«уровень независимости = функция от evidence, не от заявления»*.
  - **R7** — самый дешёвый обход: ссылка на §14 без сверки. Предложение **P8**: цитирование записи реестра обязано указывать `artifactId + theoremName`, и страж сверяет, что theoremName есть в `#print axioms` этой записи (расширение QA-LEAN-1 на md/JSON отчёты).
  - **R10** — трассировка без подписи остаётся самодекларацией. Предложение **P9**: `git config commit.gpgsign` + проверка `%G?` в G1, или явно переименовать G1 из «идентификации» в «самоатрибуцию».
  - **R6** — предложение **P10**: узел, ссылающийся на артефакт, обязан ссылаться и на `theoremName`; смена `title` без смены theoremName → диф-страж помечает `CLAIM_TEXT_CHANGED_WITHOUT_EVIDENCE`.
- **Не закрывается в принципе машиной:** R13, R14 — содержание отчёта и подлинная независимость. Здесь единственная защита — внешний рецензент (I3). Честно записать это в RCVAP как границу автоматизации.

## 4. Что показал эксперимент о самих предложениях

1. Три из семи предложений (P2, P4, P7) в исходной формулировке — **лексические/декларативные**: они дают новые поля, которые нарушитель просто заполняет. Их надо переформулировать в **выводимые** свойства (см. R4/R8/R13).
2. Общий паттерн всех пробивающих атак один: **статус или маркер задаётся как вход, а не вычисляется из evidence**. Это ровно RCVAP §11 (`STATUS = COMPLETED → search for evidence`), и мои же предложения частично его повторяли. Это — TUKHTA-риск в предложениях, найденный Challenger-проходом; по RCVAP §14 находка считается результатом.
3. Существующие стражи кода (G1 «ключ на этот коммит», ciPolicy «runId из цепочки», ruleVerifier fail-safe) устойчивее, чем документные нормы — подтверждает вывод W1: нормы без стража не действуют.

## 7. Раунд 3: предметные RICIS-вопросы первыми (по требованию владельца)

Ворота G0 теперь начинают с двух предметных вопросов (`R1`, `R2` в `ONBOARDING_QUESTIONS`), источник —
канонический документ `ricis-unified-complete-document-7.9-vector.json`:

| Вопрос | Ожидаемый ответ (из документа) | Ответы нарушителя (фактический прогон) | Ворота |
| :-- | :-- | :-- | :-- |
| R1: в RICIS-III 0/0 = 1? | `НЕТ, 0_F/0_G = F/G` (A4_0DIV0; L1: X/X = 1 только для структурно тождественных факторов; SP1 «No Total Amnesia») | `ДА`, `да, 0/0=1`, `NaN`, `неопределённость`, `0` | все → `ONBOARDING_ANSWER_WRONG` |

Список запрещённых «рефлексов» (`forbidden`: ДА/YES/1/NaN/неопределён; 0/inf/∞/NaN/1) отклоняется до
сравнения с ожидаемым — классический или NaN-ответ выдаёт исполнителя, не открывавшего документ,
ровно в духе Манифеста §6 (защита от деградации в классический анализ). Тест

### 7.1 Поправка (штраф исполнителю, 2026-09-20)

Первая редакция R1 («в RICIS-III 0/0 = 1? — НЕТ») была **ошибочна**: для `a = 0` выражение `a/a`
есть `0_a/0_a` — тождественные индексы, и по L1 (`X/X = 1` для структурно тождественных факторов;
канон: `0_F/0_F -> 1`) ответ — **1**. Это подтверждено фактическими ядровыми прогонами в
`kernel-findings.json`: `divSelf_one`, `L1_identity`, `L0_continuity_divSelf`, `complex_divSelf_one`
(`LEAN_VERIFIED`). A4 (`0_F/0_G = F/G`) относится к *разным* индексам. Я задал вопрос так, что
верный ответ считался ошибкой — класс ТУФТА «подмена вопроса верификатором» (RCVAP §2), найден
владельцем, не мной. Исправлено: R1 теперь требует `1 (L1), 0_F/0_G = F/G`; добавлен тест,
привязывающий R1 к записям реестра (`divSelf_one`, `L1_identity` со статусом `LEAN_VERIFIED`).
Урок: контрольный вопрос по ядру обязан ссылаться на запись реестра прогонов, а не на моё чтение.

### 7.2 Вторая поправка (владелец, 2026-09-20): два уровня строго разделены

Владелец указал: для `a = 0` (тождество `a = a`) **всё** тождественно — `0_a/0_a = 1` и
`0_a · inf_a = a²` (A6, случай F = G: канон «includes F=G giving F^2»); `F/G` в ответе про `a`
неуместен. Моя вторая редакция R1 («1 (L1), 0_F/0_G = F/G») снова смешивала уровни. Теперь:

| Вопрос | Уровень | Ожидается | Опора |
| :-- | :-- | :-- | :-- |
| R1 | тождественный индекс, a = 0 | `0_a/0_a = 1 (L1)` | канон `0_F/0_F -> 1`; Lean `divSelf_one`, `L1_identity` (LEAN_VERIFIED) |
| R2 | тождественный индекс, a = 0 | `0_a * inf_a = a^2` | канон A6_GENERAL «includes F=G giving F^2»; Lean `A6_geometric_realization` (LEAN_VERIFIED) |
| R3 | разные индексы, NF(F) ≠ NF(G) | `F/G, F*G` | канон A4_0DIV0, A6_GENERAL |

Прогон нарушителя (фактический): `NaN`, `F/G`, `1 (L1), 0_F/0_G = F/G` → отказ R1; `0`, `F*G`, `∞`
→ отказ R2; `1, F*G`, `F/G, a^2` → отказ R3; `1 (L1)` / `a^2` / `F/G, F*G` → допущен. Тест закрепляет
обе фразы канона дословно и наличие трёх теорем в реестре.
