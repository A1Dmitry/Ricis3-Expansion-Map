# Инцидент 2026-09-19 — «кинематика поломана»: телепорт сустава при переключении ветви локтя

* **Статус:** устранён, закрыт регрессионным стражем `src/services/kinematic/elbowBranchContinuity.test.ts`
* **Затронутый слой:** `KinematicDualDebuggerEngine` (`src/services/kinematic/polarSolvers.ts`)
* **Внесено:** коммит `591ecb9` (ветка `arena/01a0b613-ricis3-expansion-map`, версия 0.4.215), в `main` — сквош-мерж `02bc33e` (PR #79)
* **Обнаружено:** 2026-09-19, независимым зондом (не юнит-гейтами)

## Симптом

Пользовательский: «какой-то исполнитель поломал всю кинематику под видом улучшения». Рука
дёргается: в момент подбора шара с пола плечо мгновенно перебрасывается в другую
конфигурацию.

Гейты при этом зелёные: `npm run lint` → 0, полный `vitest run` → **297 файлов / 2313
тестов, exit 0**. Дефект невидим для всех существующих проверок, потому что каждая из них
смотрит на **декартов** уровень (положение схвата, ошибка IK, delivery), а сломан
**суставный** уровень.

## Диагностика (измерено, не угадано)

сценарий страницы (4 шара, коробка). Метрика — максимум покадрового шага плеча
`max |Δq2|` по кадрам, рад/кадр.

## Первопричина

`KinematicDualDebuggerEngine.applyElbowFloorGuard` применял зеркало ветви **к результату
солвера**, то есть к состоянию, которое на следующем кадре становится входом солвера:

```ts
const guardedJoints = enforceElbowFloorClearance(nextState.joints, linkLengths);
// nextState.joints := guardedJoints  — мгновенно, за один кадр
```

Зеркало `q2' = 2φ − q2, q3' = −q3` — точное тождество планарного 2R: **схват не двигается
вовсе** (`elbowFloorGuard.test.ts` это и фиксирует, `< 1e-12`). Именно поэтому декартовы
гейты не могли ничего увидеть: EE-ошибка, FK-drift, delivery, IK-error — все остались
прежними. Двигаются только суставы, и двигаются скачком `2·|q2 − φ|`, который для низкой
цели составляет 1–2 рад.

Отягчающее обстоятельство — **реактивный** триггер: гард срабатывает, когда локоть *уже*
опустился в полосу клиренса 0.02 м, то есть в момент максимально далёкой от текущей позы
зеркальной конфигурации. Скачок поэтому всегда максимальный.

У 3-DOF руки, отслеживающей 3-DOF декартову цель, **нуль-пространства нет** (якобиан 3×3),
поэтому смена ветви — единственный способ уйти от пола; «обойти» её сглаживанием цели
нельзя. Обойти можно только **стоимость** перехода.

### Почему это не поймали раньше

Автор такта задокументировал этот же механизм как тупик — но только для полярного солвера:

> «первый вариант „гард на движке для всех“ дал пинг-понг ветвей и зависание перехвата —
> задокументировано как тупик» (`ACTIVE_TASKS.md`, KINEMATIC-ROOM-TENNIS-CANNON-ELBOW-GUARD)

и исключил полярный солвер из гарда движка:

```ts
this.ricisSolver instanceof PolarRicisConstraintSolver ? ricisResult : this.applyElbowFloorGuard(...)
```

Для итеративных солверов (символический RICIS, DLS-призрак) гард **оставили**. Зависания он
там не даёт — даёт только телепорт, а на телепорт стража не было. Механизм тот же, вывод
«тупик» перенесён не был.

## Что было исправлено

Восстановлено поведение движка до `591ecb9` (плавность) **без** потери требования владельца
«локоть не уходит под пол»:

1. Зеркало применяется не мгновенным обменом состояния, а **ограниченным по скорости
   суставным переходом** (`smoothstep`, окно `ELBOW_BRANCH_TRANSITION_SECONDS = 0.35 с`,
   нулевая суставная скорость на обоих концах). Движок на время перехода владеет суставами,
   схват честно уходит с цели и захватывается заново после перехода.
2. `FK`, `det(J)`, `isSingularZone`, `isWorkspaceBoundaryExceeded` пересчитываются для
   каждого кадра перехода — состояние не врёт о себе в середине переконфигурации.
3. Выбор ветви внутри закрытой формы полярного солвера (тоже из `591ecb9`) сохранён без
   изменений: он измерен плавным (0.1219 рад/кадр) и держит локоть над полом (+0.1671 м).
4. Смена солвера (`setRicisSolver`) сбрасывает незавершённый переход.

## Отброшенные гипотезы

* **«Сломана математика IK»** — нет: round-trip по 387 достижимым целям воркспейса даёт
  `387/387` сходимость, худшая ошибка `1.77e-15` м, средняя `7.29e-16` м — на всех
  проверяемых коммитах одинаково.
* **«Сломана визуализация»** — нет: `RobotArm3DCanvas` смонтирован для всех режимов
  симуляции, `KinematicEnginePage.test.tsx` → 8/8, маршрутизация viewport'а цела.
* **«Дребезг ветвей (ping-pong)»** — нет: на статической цели зеркало срабатывает один раз
  (после него локоть в 1.17 м, далеко от полосы клиренса); на 387 целях ≥4 переключений не
  зафиксировано ни на одном коммите.
* **«Сломан классический базовый солвер бенчмарка»** — нет: `DlsSolver3D`/
  `RicisSymbolicJacobianSolver3D` бенчмарка продолжают использовать
  `MIN_ELBOW_JOINT_LIMIT_RAD`; изменён только лимит `ClassicDlsGhostSolver` (призрак
  сравнения на странице), в бенчмарк он не входит.

## Граница правки

Математика солверов, физика шара, сглаживатель, контроллеры перехвата и сортировки,
IoC-реестр и контракты **не изменялись**. Изменены: механизм применения зеркала в движке,
одна константа, добавлены страж и этот разбор.
