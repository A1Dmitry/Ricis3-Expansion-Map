# Contributing to RICIS3-Expansion-Map

Спасибо за интерес к RICIS3-Expansion-Map. Проект принимает улучшения интерфейса, документации, TypeScript-кода, интеграции Ricis.Core, тестов и proof-артефактов, если их статус и граница доверия описаны проверяемо.

## Быстрый старт

Используйте Node.js `22.22.2`–`22.x` и npm `12.0.2` или новее.

```bash
npm ci
npm run release:check
npm run lint
npm test
npm run build
```

Не используйте `--force` или `--legacy-peer-deps`. npm и `package-lock.json` — единственный нормативный менеджер зависимостей и lockfile.

## Как предлагать изменение

Сначала откройте issue с воспроизводимым сценарием, ожидаемым поведением и acceptance criteria. Для UI-ошибки приложите путь пользователя, браузер/устройство и, если проблема связана с 3D, укажите работу режима списка. Для дефекта RICIS-выражения приложите исходное выражение `F`, его дерево/контекст, применённый статус и ожидаемую границу доверия.

Каждый pull request должен быть небольшим, иметь понятное назначение и проходить полный quality gate. Функциональная правка повышает patch-версию и синхронизирует `package.json`, `package-lock.json`, `src/version.ts`, README, `CITATION.cff` и текущие release-артефакты через `npm run release:check`.

## Proof и Lean evidence

> Локальная цепочка RICIS, статический анализ TypeScript и совпадение цели в `proveSystem` не равны Lean kernel verification.

Внешний Lean source, переданный как доказательство, сохраняется дословно и не заменяется агентом. Для перехода к `LEAN_VERIFIED` или `TRUSTED_AXIOM` необходимы source hash, зафиксированный toolchain, команда запуска, фактический compiler output и `#print axioms` output без `sorryAx`. Если такой evidence недоступен, корректный статус — `REQUIRES_CORE_LEAN` или `REJECTED`.

## Правила RICIS-III

При сингулярности соблюдайте последовательность `L0 → L1 → SP2 → локальная O(1)-редукция → A1/A4 → SP3 → SP4 → A5/A6/A7`. Сохраняйте выражение `F` и его историю, не подменяйте RICIS-преобразование классическим пределом и не возвращайте `NaN` как результат пользователя.

## Безопасность и данные

Приложение не принимает, не хранит и не использует shared user API keys. Не добавляйте токены, ключи, персональные данные или секреты в исходный код, issue, тестовые данные или логи. Для security reports используйте [`SECURITY.md`](SECURITY.md).
